# FEATURES (STRICT STEPS)

### User Authentication:
Step 1 → User registers with name, email, phone, password (hashed via password_hash)
Step 2 → User logs in, session created with user_id, role
Step 3 → Auth check on every protected page redirects to login.php if not logged in

### Task System (User Side):
Step 1 → Display active tasks list (title, reward amount, category, slots left)
Step 2 → User opens task_details.php, sees full instructions
Step 3 → User submits proof (screenshot upload + text/link) via submit_task.php
Step 4 → Submission stored as "pending", user blocked from resubmitting same task
Step 5 → my_submissions.php shows status: Pending / Approved / Rejected — all labels in Bengali

### Wallet & Withdraw System:
Step 1 → wallet.php shows current balance + full transaction history
Step 2 → On admin approval of a submission, balance auto-credited + transaction logged
Step 3 → withdraw.php lets user request withdrawal (method: Bkash/Nagad/Rocket, number, amount)
Step 4 → System checks minimum withdrawal amount and sufficient balance before allowing request
Step 5 → Withdrawal status shown as Pending/Approved/Rejected in wallet history — all in Bengali

### Free Daily Spin (no payment required, no wagering):
Step 1 → User opens spin.php once per 24 hours (server-side timestamp check, no payment involved)
Step 2 → System randomly selects a prize from admin-configured prize list (weighted by admin-set probability)
Step 3 → Prize amount auto-credited to wallet + transaction logged as "স্পিন বোনাস"
Step 4 → Next eligible spin time shown to user (countdown) — label in Bengali

### Notifications & Notices:
Step 1 → notifications.php shows individual/broadcast messages sent by admin
Step 2 → notices.php shows public announcement history
Step 3 → popup.php displays active admin-scheduled popup banner on login/dashboard load

### CMS (Static Pages):
Step 1 → page.php dynamically renders admin-created pages by slug
Step 2 → Pages stored in DB with title, slug, content (HTML), status

### Admin — Task Control (Full CRUD):
Step 1 → add_task.php: Admin creates task (title, description, category, reward, proof_type, slots, status)
Step 2 → manage_tasks.php: Admin views all tasks with Edit/Delete/Activate-Deactivate buttons
Step 3 → edit_task.php: Admin updates any task field
Step 4 → delete_task.php: Admin deletes task (cascades related submissions)

### Admin — Submission Review:
Step 1 → review_submissions.php: Admin views all pending submissions with proof preview
Step 2 → Admin clicks Approve → balance credited + status updated + transaction logged
Step 3 → Admin clicks Reject → status updated with reason, no balance change

### Admin — Withdrawal Control:
Step 1 → manage_withdrawals.php: Admin views all withdrawal requests
Step 2 → Admin Approves → status updated
Step 3 → Admin Rejects → status updated, balance refunded back to user wallet

### Admin — User Management (Full CRUD):
Step 1 → manage_users.php: Admin views all users (name, email, balance, status, join date)
Step 2 → edit_user.php: Admin edits user details or manually adjusts balance
Step 3 → delete_user.php: Admin deletes/bans user account

### Admin — Free Spin Prize Control (Full CRUD):
Step 1 → manage_spin.php: Admin views all spin prizes
Step 2 → add_spin_prize.php: Admin adds prize (label, amount, probability weight, status)
Step 3 → edit_spin_prize.php: Admin updates prize details
Step 4 → delete_spin_prize.php: Admin removes a prize

### Admin — CMS Page Control (Full CRUD):
Step 1 → cms_pages.php: Admin views all static pages
Step 2 → add_page.php: Admin creates page (title, slug, content, status)
Step 3 → edit_page.php: Admin updates page content
Step 4 → delete_page.php: Admin deletes page

### Admin — Popup Control (Full CRUD):
Step 1 → manage_popups.php: Admin views all popups
Step 2 → add_popup.php: Admin creates popup (title, message, image, start/end schedule, status)
Step 3 → edit_popup.php: Admin updates popup
Step 4 → delete_popup.php: Admin deletes popup

### Admin — Notification Control:
Step 1 → manage_notifications.php: Admin views sent notification history
Step 2 → send_notification.php: Admin sends notification (target: all users / single user, title, message)

### Admin — Notice Board Control (Full CRUD):
